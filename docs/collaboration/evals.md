# Evaluation plan

No model-quality or cost-saving percentage is established by unit tests. Routing v1 explicitly reports cold-start heuristics. GPT subscription usage is unknown; API dollar comparisons cannot be converted to subscription savings.

Future opt-in evaluation should run at least 30 authorized tasks: 10 bounded scripts/tests/docs, 10 algorithms/debugging/refactors, 5 cross-module designs and 5 simulated security/permission reviews. Reuse the same fixtures across five profiles with a fixed custom policy. Record actual check outcomes, repair count, independent review, wall time, provider usage, estimated invoice cost and human intervention. Keep R3 work simulated or locally approved. Never call mock responses real evaluation results.

No automatic fallback sends extra paid requests. A host should first ask DeepSeek to diagnose and repair its failed candidate, within remaining budget, before considering GPT takeover. The new task needs a distinct ID and clear linkage in its requirements; do not automatically repeat a timed-out task with an unknown charge. Confidence/quality scoring and adaptive weights await measured evidence.


Collaboration amendment (2026-11-02): routes name only GPT or DeepSeek. The backend `DEEPSEEK_DEFAULT_MODEL` selects the actual provider model independently of profile/task type; technical pricing catalogs and audit receipts retain actual IDs for accurate accounting. Legacy model-specific route entries migrate to `deepseek`. Economy increases useful DeepSeek work, not reduces work or quality. Supply sufficient authorized context; run all necessary builds, tests and reviews. Multi-round analysis, repair and retesting are allowed within explicit budgets and permissions. Parallelism depends on dependencies, resources and safety, never on economy mode alone. Integrate verified work without reimplementing it. Failed candidates should return to DeepSeek for diagnosis/repair before GPT takeover when appropriate. Independent task/attempt bounds remain resource controls, not a cap on the overall repair workflow. No host model/account switching or DeepSeek-primary profile is added.
