# Evaluation plan

No model-quality or cost-saving percentage is established by unit tests. Routing v1 explicitly reports cold-start heuristics. GPT subscription usage is unknown; API dollar comparisons cannot be converted to subscription savings.

Future opt-in evaluation should run at least 30 authorized tasks: 10 bounded scripts/tests/docs, 10 algorithms/debugging/refactors, 5 cross-module designs and 5 simulated security/permission reviews. Reuse the same fixtures across five profiles with a fixed custom policy. Record actual check outcomes, repair count, independent review, wall time, provider usage, estimated invoice cost and human intervention. Keep R3 work simulated or locally approved. Never call mock responses real evaluation results.

No automatic fallback sends extra paid requests. A host may explicitly submit a new Pro task after reviewing a Flash failure and remaining budget. The new task needs a distinct ID and clear linkage in its requirements; do not automatically repeat a timed-out task with an unknown charge. Confidence/quality scoring and adaptive weights await measured evidence.
