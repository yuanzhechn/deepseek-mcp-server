# Policy boundaries

Generation and file uploads obey the global/project GPT-only switch. Legacy tools go through the same data, risk and atomic budget service as delegation. The final normalized request is screened, so stored history, tool schemas and extra body fields are included. Unknown model prices fail closed. Multiple candidate generation and independently billed unbounded server-side web search are refused. API keys remain runtime environment variables; neither CLI nor policy files need them.

MCP profile updates require `DEEPSEEK_COLLAB_MANAGEMENT_TOKEN`, separate from HTTP authentication. Without that token, MCP reads/routing/delegation still work, and the local CLI can change profiles. A model request cannot grant R3 approval, authorize private data, raise budgets or enroll arbitrary project roots. Only local operator configuration can do so. Do not give the model a management secret merely to bypass a refusal. This is defense against accidental/prompt-injected changes, not protection from an already trusted local operator.

`DEEPSEEK_COLLAB_PROJECT` fixes the default authorized project. Additional exact roots can be enrolled with semicolon-separated `DEEPSEEK_COLLAB_ALLOWED_PROJECTS`. Tool `project_path` cannot enroll itself. Projects and manifest paths use canonical real paths; traversal, UNC paths, sensitive paths and symlink/junction escapes are rejected. The server does not open snippet files; host-provided path labels and content remain untrusted. Approval never grants automatic shell, Git, deployment or file execution.

Private/confidential data is denied unless the local operator has explicitly enabled that scope; `secret` is always denied. Known credential patterns, private-key headers and `.env*`/SSH/AWS/Codex credential paths are blocked regardless of profile. R3/task security categories require local approval. Legacy requests have no risk field, so recognizable authentication/payment/cryptography/production-migration content is conservatively escalated; accurate semantic risk classification remains a host responsibility.

Text scanning is not complete DLP. It cannot discover every secret, prove whether a snippet was correctly classified, or determine whether opaque images contain personal information. Operators must supply only authorized minimal context. A synthetic path does not prove a snippet's origin. Do not treat these heuristics as an isolation boundary for adversarial local users or mutually untrusted HTTP tenants. One service/ledger is one operator account; separate state, credentials and transports are required for tenants.

SQLite stores metadata and usage only. API errors use existing credential redaction. MCP stdout stays protocol-only; CLI output is a separate process. New tools share the original per-client invocation limiter; HTTP host/auth/origin protections remain intact. Add deployment-specific ACLs and at-rest protections to the state directory as needed, especially on Windows where POSIX mode bits do not implement ACLs.

Before release, `npm ci`, build/tests, audit, pack dry-run and clean package startup must pass. No npm publication, main-branch merge, user Codex configuration edit, original login change or third-party message is part of this implementation.
